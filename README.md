# astrbot_plugin_chess

**网页棋盘 —— 把浏览器当作国际象棋输入法**

基于 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的国际象棋插件。在本地启动一个轻量网页，用图形化棋盘完成走子，每一步的操作结果通过 AstrBot 消息管线回流到聊天会话，由大语言模型接管对话与应手。棋盘规则由 [python-chess](https://github.com/niklasf/python-chess) 维护，插件本身不实现任何棋规判断。

## 项目背景

在聊天窗口中用文本走棋存在两个问题：一是输入成本高，`Nf3`、`exd5` 之类的记谱对不熟悉的人并不直观；二是纯文本棋盘容易看错坐标，一步笔误即导致局面偏离。

本插件将走子操作移至浏览器：用户在网页棋盘上点击两步即可完成一次合法走子，棋局状态由服务端统一维护，走子事件再以标准消息形式注入当前会话，使对话模型能够感知局面变化并继续应手。网页同时提供一个简易聊天入口，用于在横向手持设备上免切换应用地对话。

## 功能特性

- 图形化棋盘，点击走子；选中棋子时高亮全部合法落点
- 支持标准记谱（SAN）与坐标记谱（UCI）双解析，两种写法可混用
- 走子事件自动注入 AstrBot 会话，带来源前缀标记，便于模型区分事件类型
- 提供 `chess_state` / `chess_move` / `chess_new` / `chess_undo` 四个 LLM 工具，覆盖查询、走子、开局与悔棋
- 支持认输、重开、悔棋、翻转视角
- 网页内置增量消息流，聊天内容与走子记录同屏显示
- 可开启回复改道：模型回复只出现在网页消息区，聊天窗口侧静默发送
- 适配横屏设备，竖屏下自动降级为上下布局

## 环境要求

| 项目 | 要求 |
|---|---|
| AstrBot | 已安装并可正常运行，已完成 QQ（aiocqhttp）平台接入 |
| Python | 3.10 及以上（开发环境为 3.12） |
| python-chess | 1.11.2（已在 AstrBot 虚拟环境中安装） |
| aiohttp | AstrBot 内置依赖，无需单独安装 |

## 安装

1. 将本目录放入 AstrBot 的插件目录：

   ```bash
   cd AstrBot/data/plugins
   git clone <本仓库地址> astrbot_plugin_chess
   ```

2. 安装依赖：

   ```bash
   # 在 AstrBot 使用的虚拟环境中执行
   pip install -r requirements.txt
   ```

   > 在无预编译包可用的架构（如 aarch64）上，`python-chess` 可能需要从源码包安装，该库为纯 Python 实现，源码安装无需编译工具链。

3. 重启 AstrBot，或于 WebUI 插件管理页重载本插件。

4. 检查日志，出现以下内容表示网页服务启动成功：

   ```
   [chess] 网页棋盘启动：http://192.168.x.x:8765
   ```

## 配置

配置项定义于 `_conf_schema.json`，可在 AstrBot WebUI 插件配置页修改。

| 键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `web_enabled` | bool | `true` | 关闭后不启动网页服务，仅可使用聊天指令与 LLM 工具 |
| `web_host` | string | `0.0.0.0` | 监听地址，`0.0.0.0` 表示允许局域网内其他设备访问；仅本机访问可改为 `127.0.0.1` |
| `web_port` | int | `8765` | 网页服务端口，需与占用情况协调 |
| `owner_id` | string | 空 | 网页消息注入的目标 QQ 号，即网页上产生的事件归属的会话。留空则网页上的走子与聊天不会进入对话，仅刷新棋盘与消息区 |
| `redirect_to_web` | bool | `true` | 把模型回复改投到网页消息区，聊天窗口侧不再发送。只对 `owner_id` 对应的私聊生效，指令回执不受影响 |

## 使用说明

### 聊天指令

| 指令 | 说明 |
|---|---|
| `/棋` | 输出当前局面文字摘要、走子记录与网页地址 |
| `/新局` | 重置棋局，用户执白先行 |

文字棋盘采用国际通用的字母记法：大写为白方（`KQRBNP`），小写为黑方（`kqrbnp`），`·` 表示空格，左侧数字为行号，顶部为列号。下方附 FEN 串，便于在别处复原局面。

### LLM 工具

对话模型可在会话中直接调用以下工具，用户无需手写指令：

| 工具名 | 参数 | 说明 |
|---|---|---|
| `chess_state` | 无 | 返回当前局面摘要、执子方与轮次 |
| `chess_move` | `move`: string | 走子，接受 UCI（如 `e2e4`）或 SAN（如 `Nf3`） |
| `chess_new` | `side`: string | 开新局，`white`（默认）或 `black` |
| `chess_undo` | `plies`: number | 悔棋，默认退回 2 步 |

走子参数先按 UCI 解析，失败后回退至 SAN 解析，因此两种记谱可混合传入。

### 网页界面

1. 在浏览器中打开日志输出的地址，建议横屏使用。
2. 点击己方棋子，合法落点以圆点标记；点击目标格完成走子。
3. 右侧（竖屏下为下方）面板显示走子记录与对话消息，底部输入框可直接发送文本。
4. 面板按钮提供新开一局、悔棋、翻转视角、认输四项操作。

开启 `redirect_to_web` 后，模型的回复只出现在网页的消息面板里，聊天窗口侧不再发送；指令回执仍回到聊天窗口。

页面以 1.5 秒为周期轮询局面与消息增量，未使用 WebSocket。

## HTTP 接口

网页服务默认监听 `8765` 端口。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 棋盘页面 |
| GET | `/api/state` | 全量局面：FEN、8×8 棋子矩阵、轮次、执子方、走子历史、最后一步、将军状态、对局结果、合法着法表 |
| POST | `/api/move` | 用户走子，成功后注入会话 |
| POST | `/api/bot_move` | 机器人走子，仅更新局面，不注入会话 |
| POST | `/api/new` | 开新局，请求体 `{"side": "white"}` |
| POST | `/api/undo` | 悔棋，默认退 2 步，不足时退 1 步 |
| POST | `/api/resign` | 认输，请求体 `{"side": "white"}` |
| POST | `/api/chat` | 网页聊天，成功后注入会话 |
| POST | `/api/say` | 机器人向网页消息区发言，不注入会话 |
| GET | `/api/events?since=N` | 拉取编号大于 N 的增量消息，返回当前最大编号 `seq` |
| GET | `/api/health` | 健康检查 |

**请求示例**

```bash
curl -X POST http://127.0.0.1:8765/api/move \
  -H 'Content-Type: application/json' \
  -d '{"move":"e2e4"}'
```

**响应示例**

```json
{
  "ok": true,
  "msg": "e4",
  "state": {
    "fen": "rnbqkbnr/pppppppp/8/8/4P3/8/PPPP1PPP/RNBQKBNR b KQkq - 1 1",
    "turn": "black",
    "player_side": "white",
    "result": null
  }
}
```

## 工作原理

### 状态管理

`game.py` 中的 `ChessGame` 为唯一状态持有者，内部以 `threading.RLock` 保护读写。网页服务的协程与插件事件循环共享同一实例，因此无论从哪一侧走子，局面始终一致。所有对外输出均经过锁内快照（`to_json()` / `render_text()`）。

### 事件注入

网页产生走子或聊天事件后，`main.py` 构造一条 `AstrBotMessage`：类型设为 `FRIEND_MESSAGE`，`session_id` 取配置中的 `owner_id`，正文置于 `Plain` 组件内，随后调用平台适配器的 `commit_event()` 将其放入 AstrBot 消息管线。此后流程与真实用户消息一致，模型可正常接收与回复。

注入文本带固定前缀，用于标明事件来源：

- `（网页棋盘）用户刚在棋盘上走了 Nf3。` —— 走子事件
- `（网页聊天）……` —— 网页对话内容

模型据此区分棋盘事件与自然语言输入。若未找到 aiocqhttp 适配器，插件会向网页推送提示信息，不会静默丢弃事件。

### 回复改道

注入消息与网页聊天进入同一条会话后，模型的回复默认仍会发往聊天窗口。`redirect_to_web` 打开时，插件在 `on_decorating_result` 阶段截住这条回复：

1. 确认当前事件属于 `owner_id` 的私聊会话；
2. 只处理纯文本的模型回复，含图片等非文本组件的结果保持原样；
3. 将文本推送到网页消息区（`push_message("bot", ...)`）；
4. 调用 `clear_result()` 清空待发送结果，聊天侧不再发出。

推送失败时不清空结果，回复照常发到聊天，避免消息凭空消失。指令（如 `/棋`、`/新局`）的回执不受影响，仍回到聊天窗口，便于确认操作。

## 已知限制

- **单例棋局。** `ChessGame` 为单实例，非 `owner_id` 的会话会进入同一盘棋，当前未做多会话隔离。
- **状态不持久化。** 棋局保存在内存中，插件重载或进程重启后丢失。如需保留，应在此之前记录 FEN。
- **无访问控制。** 网页服务未设置鉴权，暴露于 `0.0.0.0` 时局域网内任意设备均可操作棋局。仅在可信网络中使用，或将 `web_host` 改为 `127.0.0.1`。
- **流式输出下改道不彻底。** 开启流式输出时，文本在生成过程中已分片发出，`on_decorating_result` 只能拦住最终结果，聊天窗口仍可能看到部分内容。需要完全改道时，请关闭该会话的流式输出。

## 开发与调试

- 插件重载时会主动从 `sys.modules` 中清除 `game`、`web_server`，避免因模块缓存导致改动不生效。
- 调试页面时可直接访问 `GET /api/state` 观察局面变化，`GET /api/events?since=0` 可一次性拉取全部消息。
- 若端口被占用，修改配置中的 `web_port` 后重载插件即可，`/棋` 指令返回的地址会自动跟随新端口。
